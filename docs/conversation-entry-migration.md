# 对话式规划入口迁移说明

## 默认入口

- 顶部“新建规划”进入旅行对话，并创建一次新的空对话。
- 顶部“旅行对话”进入旅行对话，并恢复最近使用的对话。
- 未登录用户完成登录后继续原动作；关闭登录弹窗不会创建对话或跳转。
- 新的 PlanningBrief 确认动作直接创建后台规划 Run，默认导航不再进入旧 PlanPage。

## 仍保留旧 PlanPage 的场景

旧 PlanPage 暂时保留为受控兼容入口，供行程详情页中的既有“修改行程”流程使用。该流程仍依赖原来的表单状态、提交动作和相关 API，不应在本次对话页迁移中删除。

旧页面和 API 可以在以下条件全部满足后移除：

1. 行程详情的修改入口能够把关联行程和修改意图带入对话 composer。
2. 对话流能够创建 revision Run，并在完成后打开新的权威行程版本。
3. 登录 continuation、失败重试、取消和刷新恢复与旧流程行为等价。
4. 迁移场景的自动化测试与桌面、移动端人工回归均通过。

## 回归边界

在迁移完成前，默认入口只切换到新对话流，不改动旧 PlanPage 的数据模型、提交 API 或行程详情页兼容调用。这样可以单独回滚入口选择，而不影响已有行程的查看和修改。
